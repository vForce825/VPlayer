# 播放页频道信息浮层设计

## 概述

VPlayer 将在全屏播放页右上角增加一张不可交互的频道信息卡。卡片沿用首页的 EPG 表达方式——频道身份、当前节目、节目进度和下一节目——同时增加经过播放器确认的媒体呈现信息，并在 VPlayer 将 25 fps 隔行源转换为 50 fps 输出时，让用户清楚感知倍帧效果。

进入频道后，卡片立即出现；用户之后唤出播放控制层时，卡片也会再次出现。稳定播放期间，卡片和控制层在 3 秒后共同隐藏。第一帧画面、`.playing` 状态和完整媒体规格必须同时出现，避免画面已经开始播放后，规格信息仍从未知或错误内容跳变。

本次设计工作同时将发行版本号更新为 1.3。

## 设计目标

- 让用户通过频道名称和台标立即确认当前频道。
- 将首页已有且有效的 EPG 表达带入播放页，同时形成 VPlayer 自己的视觉方案。
- 展示经过确认的分辨率、扫描方式、源帧率和输出帧率。
- 同时使用技术事实和易懂文案，让用户感知隔行视频的 2× 输出效果。
- 保持现有 tvOS 焦点模型，在稳定播放期间尽量减少画面遮挡。
- 首页和播放页共用 EPG 计算逻辑，避免节目跨档时间不一致。

## 不在本次范围内

- 不显示 `线路 1/1` 或其他线路数量。
- 暂不显示延迟。
- 不将完整的播放诊断指标暴露给普通用户。
- 信息卡不提供按钮或其他操作，也不进入焦点系统。
- 不显示持续波动的瞬时帧率测量值。

## 视觉设计

### 位置与结构

信息卡位于视频画面右上角，并处于 tvOS 安全区域内。背景使用深色半透明材质、连续圆角和足够的对比度，确保各种视频背景下都能清楚阅读。

卡片采用紧凑的横向信息岛结构：

1. 左侧显示频道台标，尺寸小于 APTV 的台标处理。
2. 频道名称作为最高层级文本。
3. 媒体规格作为次级信息。
4. 当前节目及其开始、结束时间。
5. 当前节目进度条。
6. 下一节目及其开始时间。

该结构是首页频道卡的播放页版本，而不是照搬 APTV。EPG 进度条继续作为 VPlayer 的主要识别特征，右上角信息岛与底部播放控制保持清晰分区。新增信息卡后，移除现有左上角单独显示的频道名称，避免同一信息重复出现。

### 媒体规格文案

没有发生帧率转换的逐行源显示为：

`1920×1080p · 50 fps`

25 fps 隔行源经过 VPlayer 的 YADIF 2× 路径后显示为：

`1920×1080i · 25 fps → 50 fps  流畅增强`

只有当前播放路径确实产生了倍帧输出时，才显示箭头和 `流畅增强` 标签。`25 fps` 和 `50 fps` 都保留单位，避免箭头被理解成没有上下文的数字换算。

规格行使用从媒体节奏和播放路径推导出的稳定帧率，不显示 `49.2 fps` 一类不断变化的窗口测量值。瞬时测量反映的是播放健康状况，而不是预期输出规格；直接展示会导致文字抖动，也会混淆两种概念。

### 信息缺失时的显示

- 播放准备期间显示 `正在检测画面规格…`，不显示 `无分辨率` 或 `无帧率`。
- 只有部分媒体属性已经确认时，只显示已确认的内容。
- 未同时确认隔行扫描方式和 2× 播放路径时，不推测或宣传 `流畅增强`。
- 没有台标时，复用首页的电视图标占位。
- 没有 EPG 时显示 `暂无节目单`，同时隐藏进度条和下一节目。
- 有当前节目但没有下一节目时，只显示当前节目和进度。

## 交互与时间规则

### 首次进入频道

1. 打开全屏播放器时，立即显示频道信息卡。
2. 频道名称、台标和 EPG 不等待媒体流，直接展示。
3. 解复用、解码和有上限的扫描方式检测期间，显示 `正在检测画面规格…`。
4. 初始扫描路径和媒体呈现信息确定之前，不发布 `.playing`，也不正式呈现第一帧视频。
5. 播放路径确定后，让完整媒体规格、第一帧画面和 `.playing` 状态同时出现。
6. 从这一刻开始计时 3 秒，随后隐藏信息卡和播放控制层。

扫描方式检测必须有明确上限。如果流缺少可靠的元数据或内容证据，在启动探测预算用尽后，使用现有的保守回退策略选择播放路径，不得为了等待分类而无限阻塞播放。

### 再次唤出控制层

- 遥控器操作唤出播放控制层时，同时唤出频道信息卡。
- 稳定播放期间，信息卡和控制层共用同一个 3 秒自动隐藏周期。
- 每次重新唤出时，共同重置计时器。
- 准备播放期间，信息卡保持显示，以便呈现媒体检测状态。
- 暂停播放时，信息卡随固定显示的控制层一起保持可见。
- 播放失败时隐藏频道信息卡和底部控制，只保留现有错误说明与恢复操作。
- 停止播放或退出播放器时，立即隐藏信息卡。
- 信息卡不接受点击，也不进入 tvOS 焦点系统。

### EPG 实时更新

- 每 30 秒重新计算当前节目、下一节目和节目进度。
- 到达节目边界时，原下一节目原子地变为当前节目，并继续选择后续节目作为下一节目。
- EPG 内容更新不重置 3 秒显示计时器。

## 架构设计

### 应用层播放展示上下文

`PlaybackRequest` 继续只承载播放引擎真正需要的输入。新增应用层播放展示值并传给 `FullScreenPlayerView`，其中包含：

- 频道标识和显示名称。
- 台标地址。
- 该频道的节目列表。

这样可以避免 UI 元数据不断扩张底层播放协议，同时让播放引擎保持独立于应用的 EPG 展示逻辑。

### 共用 EPG 展示模型

将目前写在 `ChannelCard` 内的时间计算提取为小型共用展示单元。输入节目列表和当前时间，输出：

- 当前节目。
- 下一节目。
- 限制在 `0...1` 范围内的当前节目进度。
- 已格式化或可供视图格式化的节目时间边界。

首页 `ChannelCard` 和新的播放页信息卡共同使用这个单元。字体、间距和布局仍由各自的 SwiftUI 视图负责。

### 面向产品界面的媒体信息协议

新增轻量的播放媒体信息快照，与 `PlaybackMetricsSnapshot` 诊断对象分离。该快照只包含稳定且适合普通用户查看的属性：

- 像素宽度和高度。
- 已确认的扫描方式：逐行或隔行。
- 稳定的源帧率。
- 稳定的输出帧率。
- 当前是否启用 2× 流畅增强。
- 用于拒绝过期更新的播放会话或媒体代次标识。

播放控制器通过异步流或等价的最新值接口提供该快照。应用层视图模型只订阅当前播放会话，并在换台、重试或退出时清除旧值。

### 源帧率与输出帧率

扩展 FFmpeg 选中视频轨道的描述信息，从所选视频流中取得权威或当前最佳的 FFmpeg 帧率有理数。该数值跨越 C/Swift 边界前必须完成合法性验证。

稳定输出帧率根据源媒体节奏和已确认的呈现路径计算：

- 逐行或旁路路径：输出帧率等于源帧率。
- 隔行 `metalYADIF2x` 路径：输出帧率等于源帧率的两倍。

格式化时只对已知广播帧率进行合理表达，并正确保留 29.97、59.94 等小数标准。无效有理数不得被转换成看似可信的帧率。

### 启动就绪契约

当前的播放就绪事件可能在扫描分类仍为 `unknown` 时发生。修改初始就绪条件，使 `.ready` 只有在以下条件全部满足后才能发布：

- 当前存在的音视频轨道已经满足播放就绪要求。
- 初始扫描分类已经得出结果，或已经到达有上限的回退点。
- 与该分类对应的呈现路径已经生效。
- 当前媒体代次的用户可见媒体信息已经组装完成。

对于播放开始后的真实格式变化或流不连续，仍允许呈现路径发生变化。新的媒体信息必须针对新代次原子更新；来自旧代次的迟到结果必须丢弃。

## 状态归属

`FullScreenPlayerViewModel` 保存当前媒体信息并管理订阅生命周期。`FullScreenPlayerView` 负责共用的浮层显示计时，因为它已经协调播放状态和控制层可见性。频道信息卡本身是纯展示视图，只根据频道、EPG 和媒体状态渲染内容。

自动隐藏时间从 5 秒调整为 3 秒。最终只能保留一套有效的自动隐藏策略；当前 `PlayerControlsOverlay` 内部的计时器需要与父视图的计时逻辑合并，避免父子两个计时器相互竞争。

## 错误处理与过期状态保护

- 每份媒体信息都关联当前播放会话和媒体代次。
- 换台或重试前，先取消上一会话的媒体订阅和计时器。
- 会话或代次与当前请求不一致的迟到回调一律忽略。
- 真实格式变化需要重新分类时，将规格行恢复为检测状态。
- 新的呈现路径生效后，再原子更新对应媒体规格。
- 扫描分类失败或帧率元数据缺失时，只降级界面展示，不让本来可播放的媒体因此失败。
- 播放失败继续使用现有失败浮层和恢复操作，频道信息卡不得遮挡或争夺其视觉优先级。

## 无障碍与 tvOS 焦点

- 信息卡不可聚焦，也不接受点击测试。
- 保留返回、播放/暂停和设置按钮现有的无障碍标识与初始焦点。
- 为信息卡提供简洁的无障碍描述，包含频道名称、当前节目、存在时的下一节目以及媒体规格。
- 朗读倍帧效果时使用 `从每秒 25 帧增强到每秒 50 帧`，不只朗读箭头符号。
- 遵守安全区域，并分别检查 1080p 和 4K tvOS 布局下的可读性。

## 测试方案

### 单元测试

- 共用 EPG 逻辑覆盖节目开始前、节目进行中、精确跨档点和节目结束后的选择与进度。
- 媒体文案覆盖逐行、隔行 2×、29.97/59.94、帧率缺失、分辨率缺失和无效有理数。
- 只有确认使用 2× 路径时才显示 `流畅增强`。
- 可见性状态覆盖首次显示、进入 `.playing` 后重新计时、3 秒隐藏、遥控器唤回、暂停固定、恢复播放和任务取消。
- 会话与媒体代次过滤能够拒绝上一频道或上一次重试的迟到信息。

### 播放管线测试

- 源帧率有理数能够通过 FFmpeg C/Swift 边界正确复制并完成验证。
- 扫描分类未完成时，不发布初始就绪事件。
- 得到明确分类或到达有上限的回退点后，发布初始就绪事件。
- 25 fps 隔行源使用 `metalYADIF2x` 时，报告稳定的 50 fps 输出帧率。
- 逐行源和 PsF 源走旁路时，绝不报告流畅增强。
- 格式变化只为新媒体代次产生一次原子的媒体信息切换。

### UI 与验收测试

- 进入频道后，信息卡立即出现在右上角。
- 第一帧画面、`.playing` 和完整媒体规格同时出现。
- 稳定播放 3 秒后，信息卡和控制层共同消失。
- 遥控器操作能够同时唤出两层，并且不改变原有焦点目标。
- 台标或 EPG 缺失时使用约定的紧凑降级方案。
- 较长的频道名和节目名能够正确截断，不与台标或安全区域冲突。

## 验收标准

- 播放页在右上角使用具有 VPlayer 特征的信息岛，并复用首页 EPG 的表达方式。
- 不显示线路数量和延迟。
- 确认以 2× 路径播放 25 fps 隔行源时，在开始播放的同时显示 `25 fps → 50 fps` 和 `流畅增强`。
- 界面不显示 `无分辨率` 一类技术空值。
- 初始扫描路径确定或完成有上限的回退之前，不开始呈现画面。
- 信息卡与控制层共用稳定播放状态下的 3 秒隐藏时间，并保持 tvOS 焦点安全。
- 所有新增单元测试、播放管线测试和 UI 测试通过，且不破坏现有播放行为。
